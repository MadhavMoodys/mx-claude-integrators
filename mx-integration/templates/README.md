## Claude Code

`.claude/settings.json` registers the `mx-integration` plugin. Clone the repo, open it,
trust the folder, and the skills and hooks are live — there is no command to run. The
plugin gives you:

- **`mx-integration-architecture`** — the layer boundaries, the status→exception table,
  the `${ENV_VAR}`-only credential rule, and the comment policy.
- **`/new-integration`** — the interview-and-scaffold command (already run for this repo).
- **`integration-release-checklist`** — run it before opening a PR.
- **Hooks** — literal secrets and `target/` writes are denied, commits must carry a JIRA
  key, edited Java is compiled, `pom.xml` edits trigger a vulnerability scan, and the
  turn cannot end on a failing test run.

`MX_HOOKS_DISABLED=1` bypasses every hook if one is in your way. Say so in the PR if you
used it.

## Build

```sh
mvn clean install
```

Requires Java 21 and access to `https://moodys.jfrog.io/artifactory/maven-ci-local/`.

## Run locally

Every credential is read from the environment; there are no literals in `application.yml`
and adding one is blocked by a hook. See [`parameters.yaml`](parameters.yaml) for the
authoritative list and the `$(Secret.NAME)` each maps to.

```sh
export {{VENDOR}}_BASE_URL=https://api.{{vendor}}.example.com
export {{VENDOR}}_API_KEY=...
mvn -pl {{vendor}}-api spring-boot:run
```

Health: `http://localhost:3000/internal/health`.
API docs: `http://localhost:3000/swagger-ui.html`.

## What still needs filling in

The scaffold generates everything mechanical. What it cannot know is {{Vendor}}'s own
semantics, and those are marked with ticket-tagged TODOs:

```sh
grep -rn "TODO(" --include=*.java --include=*.yml .
```

Each one is a real gap — the request shapes in `{{Vendor}}Client`, the DTOs and parsing
in `ResponseTransformer`, and the token endpoint in `TokenManager` (delete that class
outright if {{Vendor}} authenticates with a static header key).

## Before opening a PR

Run the `integration-release-checklist` skill. The one gate it cannot automate is the
mandatory JFrog **Docker PR repository scan descendants** review — Critical and High
findings must be triaged there regardless of what the local vulnerability hook reported.
